## Зачем

У каждой формы — блок «Деньги» (слот `extra` под шапкой, над метой; имя на экране не
пишем). В блоке **одно главное число — самое актуальное на сегодня**, остальные его
поддерживают и помогают решать. Сквозное правило: **главное — факт, где он есть**;
оценка главная только там, где факта ещё нет.

Цен в модели три — оценка (`Item.estimated_cost`), счёт (`PurchaseLine.price`), партия
(`Lot`) — и блок становится местом, где они встречаются и видно, где разошлись.

## Числа по формам (★ — главное)

| Форма | ★ Главное | Поддержка | Предупреждение / команда |
|---|---|---|---|
| Изделие покупное | **последняя цена по счёту** (штука; последний по дате зафиксированный заказ или поставка без заказа; нули-образцы пропускаем) | средняя (взвешенная по кол-ву), максимальная, на складах на сумму | оценка разошлась с последней ценой > 10% → ⚠ + команда **«Взять в оценку»** |
| Изделие производимое | **живой роллап по составу** | позиции без цены, 3 самых дорогих компонента по вкладу, на складах на сумму | роллап ≠ `estimated_cost` (до копейки) → ⚠ «оценка устарела» + **«Переоценить»** |
| Проект | **потрачено** | % бюджета, % плана; план, бюджет, запас/перерасход; **сверх потребности** (план / чистая потребность − 1, «+22%», раскладка причин в подсказке) | позиции без оценки (как сейчас) |
| Закупка | **закупка** = заказано по счёту + осталось по оценке (всё закрыто → чистый факт) | заказано по счёту, осталось по оценке, оценка закупки, **счёт к оценке %** (по закрытым позициям, против ТЕКУЩЕЙ оценки), потребность, переплата | без оценки (как сейчас) |
| Заказ | **сумма по счёту** | получено, ждём от поставщика (получено + ждём = счёт) | без цены (как сейчас) |
| Поставка | **сумма по УПД** (из меты — в блок) | из заказа: по заказу на эти позиции, расхождение | — |
| Передача / Списание / Требование / Инвентаризация / Перемещение | **передали / списали / перевели / нашли / переместили на сумму** | — | — |
| Комплектация | **израсходовано на сумму** (единая сумма ордеров) | — | остальное — при отдельном разборе комплектации |
| Место хранения | **лежит на сумму** | уточнит Иван при запуске складского контура | — |
| Контрагент | **ждём от него** (обязательства, не закрытые УПД) | сумма по всем УПД от него | панели «Поставки»/«Передачи» остаются |

Снято с панели проекта: **себестоимость** и **экономия** → BACKLOG (своего не паяем ещё
полгода).

**Вид:** главное — первым слева, крупнее (~22px против 15px), отделено линией;
поддержка справа обычным размером. Одна роль `Stat main`.

## Ф0 — Схема и учётный канон партии

Канон (сверен с SAP/Odoo/1С): **первична сумма, цена — производная; «стоимость +
количество, последний забирает остаток».**

- [x] `Lot.unit_cost` (цена штуки, 2 знака) → **стоимость партии** (сумма строки УПД);
      цена штуки — только вычисляемая.
- [x] Расход партии (пайка, передача, списание, отпочкование, перемещение) —
      пропорциональная доля стоимости до копейки; **движение, обнуляющее партию,
      забирает весь остаток стоимости**.
- [x] Поставка из заказа: стоимость партии = цена строки × поступившее / заказанное
      (вместо округлённой штуки, `engine.py` ~1996).
- [x] Прибор из комплектации: стоимость = Σ стоимостей израсходованного
      (`_device_unit_cost` → стоимость, без деления и округления).
- [x] **Дата заказа обязательна к фиксации:** CHECK `purchase_locked_has_date` +
      прикладной гейт в `lock_purchase` (канон Ф12e/Ф14). В dev-снимке 17 зафиксированных,
      без даты 0 — **перед выкатом проверить свежий снимок прода.**
- [x] Миграция с переносом данных: стоимость = qty × unit_cost; партии поставок из
      заказа — пересчёт точно из цены строки.
- [x] Обе диаграммы README, тесты, запись в журнал.

**Решено на старте фазы** (автономный проход, рекомендации Claude — JOURNAL 2026-10-19 «Волна 26, Ф0»):
1. Где живёт стоимость движения — в проекции (`StockMovement`, считается на
   `rebuild_movements`) или вычисляется на чтении. Грабля: движения — пересобираемая
   проекция, порядок «кто последний» обязан быть детерминированным при каждой пересборке.
2. Ввод строки поставки руками — **стоимость строки УПД** (как цена строки заказа в в24)
   вместо цены штуки (`ReceiptView`, `update_receipt_lot`).
3. Инвентаризация: стоимость найденной партии с предшественником — доля стоимости
   предшественника (сейчас наследуется цена штуки, `views.py` ~1695).
4. Требование: дочерняя партия получает долю стоимости источника по тому же правилу
   расхода.

Около 42 чтений `unit_cost` в движке, 8 во вьюхах, 2 в админке, ~20 во фронте, 42 в тестах.

Фаза **выкатываемая отдельно**: канон проверяется на снимке прода (`pull_prod.sh --load`)
до того, как поверх строится интерфейс.
