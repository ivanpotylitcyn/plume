- ✅ ~~**Админка: восемь пунктов сайдбара на ОДНУ таблицу (пережиток MTI).**~~ **СДЕЛАНО
  2026-07-29 (волна 19, Ф16).** Замечено Иваном
  2026-07-27 после Ф14: в админке видны «Ордера» + семь видов (Поставки/Комплектации/
  Инвентаризации/Требования/Передачи/Списания/Перемещения) — а таблица теперь одна.
  Артефакт: per-kind админки были единственным способом править семь таблиц, витрина
  «Ордера» — способом увидеть их вперемешку. Фронт (`<OrderForm kind=…>`),
  `FIELD_MATRIX` (единый row-set B) и БД уже считают их одной сущностью; админка —
  последнее место, где их семь.
  **Схлопывается штатно:** единственное, ради чего держалась семёрка, — разные инлайны
  по видам (у комплектации строка с `date`, у передачи с `display_name`, у поставки и
  инвентаризации строк-`StockLine` нет вовсе — там born-лоты). Закрывается хуками
  `get_inlines(request, obj)` / `get_fields(request, obj)` по `kind`. Попутно умирает
  кастомная колонка `open_child` с `reverse()` по соглашению об именах.
  **Под косметикой — вопрос крупнее:** админка правит `StockLine` и лоты **мимо
  движка**, без `rebuild_movements`. После Ф15 («замок гейтит склад») это станет
  опаснее: инвариант «движения ⟺ документ зафиксирован» админка сможет нарушить молча.
  То есть решать надо не «восемь пунктов или один», а **чем админка теперь является**
  (полноценная правка / только просмотр и удаление / принять дрейф). README до сих пор
  утверждает «админка — основная поверхность ввода, витрины React read-only поверх
  этого» — с волн 13–19 это перевёрнуто, строку тоже поправить.
  **Как закрыто (развилка Ивана: «косметика + read-only движковым»):** семь per-kind
  регистраций сняты, `StockDocumentAdmin` — единственный пункт «Ордера» с
  `get_fields`/`get_inlines`/`get_readonly_fields` по `kind` (`open_child` умер вместе
  с семёркой; 20 регистраций → 13, сайдбар 20 → 12). Граница движка: `locked` и `kind`
  read-only, удаления ордера нет вовсе (снос чистит born-лоты, движения и **файлы**
  вложений — каскад БД оставил бы сирот), `Lot`/`StockMovement`/`StockLine`/`Attachment`
  — витрины. Утверждение «админка — основная поверхность ввода» нашлось **в docstring
  `admin.py`, а не в README** (в README его нет вовсе) и переписано.
  *Всплыло на приёмке Ф14 (2026-07-27), закрыто в Ф16.*
