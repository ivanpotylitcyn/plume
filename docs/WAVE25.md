# Волна 25 — Гибкая ширина: список режима и формы

**Статус: В РАБОТЕ.** План 2026-10-18; разведка на снимке прода; решение Ивана принято
(JOURNAL 2026-10-18). **ЗАКРЫТА 2026-10-19: Ф0–Ф4 приняты Иваном.** Тач на телефоне проверят пользователи
после выката. JOURNAL 2026-10-19: «Ф0+Ф1», «Ф2», «Ф3», «Ф4». Лестница приоритетов
колонок принята 2026-10-19 (описание — первым).

## Зачем

Живые названия стали длиннее — список режима (240px) их режет. Нужна ширина «как в VS
Code»: тянется мышью и пальцем, прячется целиком. А сужение рабочей области вскрыло
главное: **горизонтальная прокрутка тела таба (волна 23, Ф3) — компромисс, который уже
мешает на практике.** При быстром перебивании количеств в позициях все поля строки
должны быть видны сразу. Поэтому в тесноте прячем менее важные колонки, а прокрутка
остаётся только последней страховкой (телефон).

Опоры решения: экраны у команды преимущественно широкие; список можно убрать целиком —
и тогда помещается всё.

## Разведка (2026-10-18, замеры headless-Chrome на снимке прода)

Матрица: 7 форм × окно 1440/1280/980 × список 240/400 × все табы × просмотр/правка.

**Рамка держится везде**: рабочая область и шапка не переполнились ни разу. Пиксельные
ширины в теме — «предпочтение с потолком» (`max-width: 100%`), медиа-запросов в CSS
нет ни одного.

**Пол таблиц** — единственная резиновая колонка «Описание», всё остальное фиксировано
ролями (`--col-*`, треки `.prow`):

| Список | Фикс. скелет | Где |
|---|---|---|
| Лента документов (`c-cp`/`c-no`/`c-date`/`c-count`/`c-money`) | ≈ 860px | Заказы проекта/контрагента/аккаунта |
| `.prow` «Приборы» / «Потребность» | ≈ 810px + описание | проект, закупка |
| `.prow--alloc` «Строки» закупки | ≈ 720px + описание | закупка |
| Строки заказа (правка) | ≈ 790px + описание | заказ |
| Строки поставки (правка) | ≈ 830px + описание | поставка |

Без прокрутки нужна рабочая область ≳ 1030px. Уже сегодня 1280/240 → «Приборы»
прокручиваются; 1440/400 → описание ленты 83px («Матриц…»); 980/240 → почти все
многоколоночные табы едут на 250–335px.

**Две семьи списков ведут себя по-разному**: в `table.grid` описание сжимается до
огрызка (`max-width: 0`), в `.prow` у него пол 140px (`minmax(140px, 1fr)`). Ширины
колонок `table.grid` при `table-layout: auto` договаривает браузер: у строк поставки
«Кол-во» и «Цена» получают по ~300px, а описание — 279.

## Как это сделано в VS Code (исходники `sash.ts`, `splitview.ts`, `sidebarPart.ts`)

- Sash 4px; подсветка `hoverBorder` после 300мс; `touch-action: none`; мышь и тач одним
  путём; во время драга курсор `col-resize` на всём документе; двойной клик = сброс.
- Сайдбар: min 170, max ∞, `snap` (утянули меньше половины минимума — спрятался),
  приоритет `Low` — изменение окна сначала забирает редактор.
- Ширина хранится на машину (`StorageTarget.MACHINE`), не в профиле.
- Каждая часть получает свой `layout(width)` — адаптация к своей ширине, не к окну.

## Принципы волны (чтобы не всплыло ни на телефоне, ни в новых окнах)

1. **Форма подстраивается под ширину РАБОЧЕЙ ОБЛАСТИ, а не окна.** Ни одного
   `@media (width)` для вёрстки форм. Единственный уместный медиа-запрос — `(pointer:
   coarse)` для зоны захвата sash: он про устройство ввода, а не про ширину.
2. **У каждого пикселя — потолок контейнера.** Фиксированная ширина = предпочтение.
3. **Приоритет колонки — свойство РОЛИ** (`c-count`, `c-date`, `c-cp`…), а не
   конкретной таблицы. Новая таблица на ролях получает поведение даром.
4. **Шапка — один канон на все формы** → её адаптация может стоять на литеральном
   пороге `@container`. Списки разные → их подбирает измеритель, а не пороги.

### Ф1. Шелл: изменяемая ширина и скрытие списка ✅
_Сделано 2026-10-19: `Sash.tsx`, `--side-min/-def/--work-min/--sash-w` в `index.css`,
`--sash-hover` в темах; ⌘B — по `e.code`. Проверено сценарием CDP (драг, потолок, snap,
⌘B в русской раскладке, клик по активному режиму, двойной клик, перезагрузка, ресайз
окна, стрелки). За Иваном — тач на телефоне._
- Состояние = ЖЕЛАЕМАЯ ширина; действующую считает CSS — ресайз окна без JS:
  ```css
  .app { grid-template-columns: 48px
    clamp(var(--side-min), var(--side-w), calc(100vw - 48px - var(--work-min)))
    minmax(0, 1fr); }
  ```
  Это `LayoutPriority.Low`: список держит ширину, пока области хватает; окно
  выросло — ширина вернулась. Ориентиры: `--side-min` ≈ 180, по умолчанию 240,
  `--work-min` ≈ 560 (пол шапки).
- Sash — pointer events + `setPointerCapture` (мышь/тач/перо одним путём),
  `touch-action: none`, зона 4px, на `(pointer: coarse)` ≈ 16px; подсветка токеном
  темы (оба `themes/*.css`) после 300мс; курсор на документе во время драга; двойной
  клик → 240. Во время драга пишем CSS-переменную прямо в DOM, React-стейт — на
  `pointerup` (иначе `App` перерисовывается 60 раз в секунду).
- Скрытие: snap (меньше половины минимума) + клик по АКТИВНОМУ режиму панели режимов
  сворачивает/разворачивает (как в VS Code) + ⌘B / Ctrl+B.
- Хранение — `localStorage` (на устройство): ширина и признак «скрыт». Не UserProfile —
  у телефона и десктопа ширины разные.
- `role="separator"`, стрелки с клавиатуры — по возможности.
